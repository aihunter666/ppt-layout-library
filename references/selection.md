# 内容组织与结构选择

结构和视觉风格是两个决策。布局原图用于判断空间关系；字体、色彩、图像、材质和动效由当前项目决定。

| 内容关系 | 首选检索分类 | 重点核对 |
| --- | --- | --- |
| 全场议程、章节导航 | 目录页 | 条目数、章节名长度、顺序与分组 |
| 章节开场、内容分隔 | 章节页 | 章节编号、标题与短引言 |
| 结束、致谢、问答 | 尾页 | 结尾目的和观众下一步动作 |
| 同级要点、功能、模块 | 并列、纯文本 | 条目同层级，数量与篇幅接近 |
| 两个对象逐项比较 | VS对比、并列 | 相同维度、单位、信息粒度 |
| 一个结论及多个支撑 | 总分结构、总分、关系 | 主次清晰，支撑确实解释主项 |
| 有先后顺序的步骤 | 流程 | 步骤数、方向、分支与依赖 |
| 阶段会重复、带反馈 | 循环、PDCA管理循环法 | 回路与反馈位置确实存在 |
| 层级、优先级、基础到顶层 | 金字塔、递进 | 空间层次有语义，不暗示假比例 |
| 某个结果的原因分类 | 鱼骨图、关系 | 原因假设与已验证因果分开 |
| 有日期的演化和里程碑 | 时间轴 | 时间跨度、节点密度、间隔尺度 |
| 数值、证据、阶段产出 | 数据成果 | 指标口径、单位、基准及图表类型 |
| 图像、界面、案例说明 | 图文表达 | 图片数量、比例、裁切与文字长度 |
| 人物或团队 | 人物介绍 | 人数、头像与履历容量 |
| 特定分析模型 | 同名专业分类 | 内容确实符合该模型各维度 |

## 候选判断

每个候选先核对逻辑关系，再看内容数量、文字密度、视觉素材、阅读顺序。不要因为某个缩略图好看就改变内容逻辑。过密时先拆分页面或精简重复说明，不优先缩小正文。

同一页的候选要有真实差异，例如“横向完整流程”“中心总览加分支”“左侧主结论加右侧证据”；单纯改色或圆角不是结构方案。不同关系的候选只有在内容支持两种组织逻辑时才有意义。

要点数、字号、实际文案长度、图片比例需要在查看缩略图后判断，本库没有这些可靠的机器标签。不从索引排名或相似标签直接声称某个布局最优。

## 预览输出

使用相同内容和相同风格制作 2–4 个可对照预览，按用户目标调整数量。每个方案用一句话说明为何适合，以及最主要的取舍。实际预览必须打开检查，避免缺字、文字溢出和图形误导。

页面规格可记：布局编号、源分类、语义关系、内容槽位、第一视觉、阅读顺序、与源结构相比的调整。最终演示页不需要显示这些制作说明。

如果用户只需要“给我几个可选结构”，先展示本库缩略图并标明尚未试排；如果用户明确要“预览稿”，则必须把实际内容排进去。
